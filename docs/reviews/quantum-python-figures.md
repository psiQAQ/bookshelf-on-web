## 提取方法（非 OCR）

- 图注在原书中是独立的 `FIGURE N.M` 行，图注文字在其下一行，两者之间有横线；全书共 59 条图注，编号 1.1–14.3，无遗漏、无重复。
- 全书只有 24 页含内嵌位图（37 个 xref），708 页含矢量绘图，因此图片不能用 `get_images()` 直接取出：脚本取「图注上方最近的文本块底部 → 图注行顶部」之间的竖条带，合并条带内全部矢量绘图与置入位图的矩形得到裁剪框，再用 MuPDF 以 220 DPI 栅格化为 PNG。
- 该流程只做几何裁剪与栅格化，不读文字、不做 OCR，也不重绘图形。
- 提取脚本：`.local/extract_figures.py`（临时工具，未加入项目依赖）；机器可读清单：`.local/figures-manifest.json`；两者均在 `.gitignore` 忽略范围内。
- 一致性核对：正文里出现的图号与图注行一一对应，59 个图号无缺、无重；第 15、16 章没有插图。

## 文本层的坑（影响后续翻译）

- MuPDF（PyMuPDF）读这一版 PDF 的文本层会丢字符：全书 1,486,750 个字符里有 3,013 个 U+00AD（软连字符）被插到本该是字母的位置（如 `wor­flow d­fines` 实为 `workflow defines`，`co­nflicts` 实为 `conflicts`）。
- pypdf 6.12.0 读同一页没有该问题（软连字符 0 个、替换字符 0 个），`extraction_mode="layout"` 还能保住表格列与代码缩进，但会有字间空格残留（`Ta b l e 2.1`）与两端对齐造成的双空格。
- 结论：几何、绘图、裁剪继续用 PyMuPDF；纯文本与版面用 pypdf 按字体（Times-Roman 正文 / LetterGothic 代码 / TradeGothic 标题）分类重建，翻译阶段不得使用 PyMuPDF 文本。
