# 正文结构与内容完整性

机器检查用来找疑点，**不能代替逐页核对**。这一类的共同根因是：提取器把等宽或短文本整块判成代码/公式，正文被搬走，原位置只剩空壳。

## 1. 空项目符号与断句

**现象**：页面出现一排空的圆点；或句子停在「…它用于修改形状为」然后跳走；清单只剩外壳。本书初查 **68 个空项目符号 + 9 处断句**，例如 §2.1.1「NumPy 基础」的六组函数清单（创建/重组/访问/索引/算术/线代）与六个子模块，以及 `KohnShamDFT`、`gRPC`、`libblas.so`、「m 个电子」、`14792×2450/4≈900 万`、`C(n,k)·C(m,k)·k!` 这些被截断的句子。

**成因**：整块等宽文字被判成 CODE 后搬进围栏，原位置的列表标记留下；行归并（`abs(dy) <= 2.6`）会把多项内容挤进同一条记录，导致句子被切开。

**机器判据**（`tests/test_chapter_markup.py`）：

| 测试 | 判据 |
| --- | --- |
| 空项 | `r"^\s{0,6}[-*+]\s*$"` |
| 悬空列表项 | 含「例如／包括／如下／分别／由」且以横线结尾 |
| 引导语后必须有内容 | 以「例如：／包括：／如下：」结尾的列表项，其后首个非空行必须是列表、代码、图片、表格或展示式 |

它不验证嵌套层级，也不验证内容是否与原书一致 —— 内容必须回 PDF 补。

**修复**：回 PDF 文本层逐项补回，函数名用行内代码，子项缩进两空格。**不能只删空 `-`**：删掉空壳只是让测试闭嘴。整理异常项目符号（如去掉多余 `-`）也不等于缺失内容已补齐。

## 2. 文件结构图（目录树）

**现象**：围栏里只剩一行行文件名，层级全靠猜；跨页的树被拆成两块。
**成因**：树的连接线是 PDF 矢量图形，文本层没有；缩进不足以定父子关系。
**判据**：搜「目录结构／结构如下／布局如下」，找「所有非空行都是纯文件名」的围栏。**仓库没有自动断言。**
**修复**：看 PDF 页面结合文字横坐标确认层级，用 `├──`/`│`/`└──` 重画，每级四空格，跨页合成一块。本书三处：`chapters/01-environment.qmd` §1.1.2.1 mypkg、§1.1.2.3 core_repo/extensions、§1.4 项目布局。
**验收**：节点、父子关系、末支连接符逐一对照页面；源码与渲染都保持树形。

## 3. 被误裁成图片的正文

**现象**：「公式图」里其实是正文段落、章节标题（`10.8 OpenMP`）、英文正文（Hückel/SAP 模型）、`or err` 页边碎片。
**成因**：`is_math_line()` 的兜底 `return len(text.split()) <= 6` 把短正文判成公式；裁剪后原位置留白，读者看到图里是文字。
**判据（人工）**：找夹在连续列表项之间、或紧邻代码/正文的图片；找重复的章节标题、段落突然中断。命中即为候选，必须回 PDF 确认。
**修复**：纯文字恢复为完整译文；已有标题只保留一次；页边碎片确认无独立内容后删除。同步图片引用与 `metadata.yaml` 的 `assets` 声明，**保留仍被引用的锚点**。
**验收**：图片前后语义连续，无漏段、无重复标题、无孤立碎片。

## 4. 表格图片后的残片

**现象**：表格 PNG 后面又出现一块错序的围栏文本（本书删过 10 块）；或表格前的句子只剩半句（「Numba 和 Cython…」等 5 处句首被抽走）。
**成因**：表格裁图后，文本层副本仍留在正文；句首的标识符又被单独分离出去。
**判据**：逐表检查图注与下一段正文之间的围栏；`find_prose_in_fence` 可辅助，但纯标识符碎块会漏。
**修复**：必须对照 PDF 表格与 PNG，**确认内容完整重复后才删**；独有内容要恢复，不能顺手清除。
**验收**：表头、单元格、脚注无缺失，图后不重复转录，后续句首完整。

## 5. 英文残留与围栏内正文

**现象**：`arrangedasD0, D+1, D-1, D+2, D-2.Forsimplicity,we haveomittedthereordering` 这类没翻译、粘连又压平的英文；中文正文被包在围栏里。
**成因**：提取误分类 + 翻译时跳过代码区域。
**机器判据**：
- `find_prose_in_fence(path)`：`prose_in_fence:cjk`（中文 ≥6 字）或 `prose_in_fence:english`（无中文、英文 ≥30 字母、≥4 词、无代码字符）—— **候选清单**；
- `find_english_residue(path)`：围栏、展示式、文献区之外的英文段落；
- `find_formula_remnant(path)`：压平副本（见 [formulas.md](formulas.md)）。

有反引号、中英混排、粘连文本的句子可能绕过规则。
**修复**：逐条区分「正文 / 表格碎片 / 合法 docstring / 真实会话输出」；会话外的英文回 PDF 补译，不批量删行。
**验收**：严格项为零；`prose_in_fence` 是待甄别清单（本书 100 条），测试只约束不增长。

## 6. 图片、图注与锚点

**现象**：删图后 `metadata.yaml` 资产声明没更新；图注编号错位；锚点丢失或重复。
**成因**：图片、正文、元数据分开改，没做联合核对。
**判据**：`tests/test_quantum_notes.py` 要求图片存在、不重复引用、紧随对应编号的非空图注、资产引用集合 == 声明集合；本书固定 **59 图 / 18 表 / 222 个 `$$` 块 / 223 个 `eq-` 唯一锚点**（这不是「全书锚点总数」）。`scripts/publishing.py` 的 `check_qmd(path)` 只拒绝单文件内显式锚点重复。
**修复**：维护「源页 → 图片 → 图注 → 锚点」对应表；替换或合并内容时保留跳转身份。
**验收**：上述测试通过 + 人工核查每图锚点。现有图片测试**不保证每张普通图都有锚点**。

## 新增一本书的执行顺序

1. 建章节、图表、列表与源页清单；先逐页核对目录树、表格、疑似正文截图。
2. 跑结构测试与正文审计：

   ```bash
   python -m unittest discover -s tests -p "test_chapter_markup.py"
   python scripts/audit_prose.py --check
   python -m unittest discover -s tests -p "test_audit_prose.py"
   python -m unittest discover -s tests -p "test_quantum_notes.py"
   ```

   这些入口绑定本书；新书先适配路径与基线数字。审计可复用 `audit_book(book: Path = BOOK) -> dict`。
3. 人工处理疑点后复跑，再看渲染后的分段、列表与跳转。
4. `python scripts/validate.py --strict` 只检查登记、资产、来源映射与审批，**不证明全文完整**；它会写 `reports/validation.json`，纯只读核查时不要跑。

## 陷阱与反例

- **摘要不是翻译**：不能用一句概括替换清单、表格或长段正文。
- **快照覆盖**：禁止 `git show HEAD:path > 同名文件` 存基线 —— 重定向先截断目标，会覆盖工作区改动；只读查看用不带重定向的 `git show`。
- **「句子被吃」**：pandoc 把连续普通行并成一段，所以段落之间必须留空行；反过来，看到一句断掉先查是不是漏了空行，别急着补字。
- **树形缩进**：用空格不用 TAB；文件名齐全不代表层级正确。
- **锚点计数假通过**：数量相同不代表身份相同，要比较名称与引用目标。
